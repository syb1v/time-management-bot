# Time Manager

Приватный Telegram-бот для режима дня, школы, домашнего задания и записей «Сотки».

## Возможности

- импорт расписания 11Г из markdown;
- импорт сентябрьских материалов «Сотки» с дедлайном до следующего выпуска;
- планирование сна, дороги, еды, отдыха, ДЗ и фокус-блоков;
- ввод общей длительности ДЗ;
- отметки выполнения, частичного выполнения, переноса и пропуска;
- недельная сводка, статистика и PNG-график;
- напоминания перед каждым блоком;
- доступ только для двух заданных Telegram ID.
- одна сохраняемая панель вместо ленты сообщений: ввод ученицы удаляется после обработки;
- точное время эфира «Сотки», преподаватель, статус просмотра/ДЗ и прямая ссылка;
- статистика за неделю, месяц, полгода и год.

## Локальный запуск

Требуется Python 3.12 или новее.

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env
```

Создай бота через `@BotFather`, помести токен в `BOT_TOKEN` файла `.env`, затем запусти:

```bash
.venv/bin/python -m time_manager.main
```

В BotFather рекомендуется отключить добавление бота в группы. Приложение дополнительно проверяет Telegram ID для каждого сообщения и callback-запроса.

## VPS с Docker

```bash
cp .env.example .env
docker compose up -d --build
docker compose logs -f bot
```

Файл базы находится в `data/time-manager.db`. Для простой резервной копии останови контейнер, скопируй каталог `data`, затем снова запусти контейнер:

```bash
docker compose stop bot
cp -a data "data-backup-$(date +%F)"
docker compose start bot
```

## Настройка расписаний

Школьный импорт читает секцию «Списком по дням» из `raspisanie_11g.md`. Импорт «Сотки» читает строки вида `- 8 сентября — ≈ 2,5 ч` из `vebinary_sotka_sentyabr_2026.md`. Импорт идемпотентен и выполняется при запуске.

## Подключение API «Сотки»

Приложение читает `GET https://admin.sotkaonline.ru/api/v1/calendar` напрямую и оставляет только три курса:

- Русский язык с Дашей | ЕГЭ 2027;
- Обществознание с Алексеем | ЕГЭ 2027;
- Профильная математика с Александром | ЕГЭ 2027.

Интерфейс старой платформы не используется. Вайбкодинг, обществознание с Ксенией и остальные посторонние курсы отбрасываются. Два математических блока одной даты складываются.

API использует Bearer JWT, а не cookies. У обнаруженного токена заявлен срок жизни около года. Скопируй значение заголовка `Authorization` без слова `Bearer` в локальный `.env`:

```dotenv
SOTKA_API_TOKEN=eyJ...
SOTKA_SYNC_DAYS=90
```

Не добавляй токен в `.env.example`, README, Git или сообщения. При ошибке или истечении токена бот сохраняет уже загруженные события в SQLite. Если токена нет, при запуске используется markdown-файл.

Бот синхронизирует календарь при запуске и ежедневно в `03:15 МСК`. За семь дней до окончания JWT синхронизация останавливается и владельцу приходит предупреждение: нужно получить новый токен тем же способом. Cookies платформы для работы бота не нужны.

Для будущего исследования можно экспортировать HAR, но перед передачей третьим лицам удали:

- заголовки `Cookie` и `Authorization`;
- access/refresh tokens;
- логины, телефоны, email и ФИО;
- тела запросов и ответов с персональными данными.

HAR-файлы игнорируются Git. Не передавай профиль Zen и не копируй браузерное хранилище. После определения endpoint API должен быть реализован как отдельный источник, а ключи должны передаваться только через `.env`.
